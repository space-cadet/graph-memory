**Description**: Create an OpenClaw skill wrapper that exposes graph queries as first-class tools for the agent. The skill provides structured graph search, statistics, and relationship traversal without requiring the agent to run raw shell commands.

## Goal

Enable the agent to query the graph-memory system during conversations without using `exec` to run Node scripts. The skill should:

1. Accept natural language queries
2. Return structured, readable markdown
3. Handle errors gracefully (graph unavailable, no results)
4. Be discoverable via standard skill loading mechanisms

## Rationale

Currently the agent can query the graph via `exec`:
```bash
node code/graph-memory/scripts/search-graph.cjs "quantum" --deep
```

This is:
- **Fragile** — depends on cwd, relative paths
- **Unstructured** — raw JSON or text output
- **Slow** — shell spawn overhead + Node.js cold start (~200ms)
- **Unreliable** — better-sqlite3 may not be available in all contexts

A proper OpenClaw skill provides:
- **Fast** — in-process function call (<10ms)
- **Structured** — typed parameters and return values
- **Reliable** — handles DB path resolution internally
- **Discoverable** — appears in agent tool list

## Implementation Plan

### Phase 1: Skill Structure
```
skills/graph-memory/
├── SKILL.md                 # Skill definition
├── scripts/
│   └── query.js             # Wrapper around query-bridge.cjs
└── _meta.json               # Skill metadata
```

### Phase 2: Query API
The skill exposes three functions:

1. **`graph_search(query, options)`**
   - Input: `query` (string), `options.type` (optional), `options.deep` (bool)
   - Output: Markdown list of entities with mention counts and types
   - Uses: `search-graph.cjs` → SQL `LIKE` queries

2. **`graph_stats()`**
   - Input: none
   - Output: Entity counts, relationship counts, top entities
   - Uses: `knowledge-graph.cjs stats`

3. **`graph_related(entity, depth)`**
   - Input: `entity` (string), `depth` (number, default 2)
   - Output: Relationship tree in markdown
   - Uses: BFS traversal via `knowledge-graph.cjs`

### Phase 3: Error Handling
- Graph DB missing → return "Graph memory not initialized"
- No results → return "No matching entities found"
- better-sqlite3 missing → fallback to sqlite3 async driver

### Phase 4: Integration Test
- Verify: `graph_search("chimera")` returns project entity
- Verify: `graph_stats()` shows >9,000 sessions processed
- Verify: `graph_related("deepak", 2)` returns person + projects + tools
