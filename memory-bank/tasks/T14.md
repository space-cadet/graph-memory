**Description**: Nightly cron pipeline that queries the graph for emerging patterns and converts them into mulch learning records. Creates a feedback loop: sessions → graph → mulch → better agent memory.

## Goal

Automatically discover patterns from the graph and record them as structured learnings in the mulch system. Avoid manual review — only high-signal, novel patterns should be recorded.

## What Gets Recorded

### 1. Rising Entities (pattern type: `observational`)
- Entities whose mention count increased >50% in the past 7 days
- Example: `chimera-chat` went from 3 → 12 mentions → "Active development on chimera-chat detected"

### 2. New Entity Types (pattern type: `convention`)
- First appearance of entity types not seen before
- Example: First `decision` entity → "Decision tracking now active in sessions"

### 3. Repeated Errors (pattern type: `failure`)
- Error entities with >3 mentions in 7 days
- Example: `git push rejected` → "Frequent git push failures — check branch protection"

### 4. Topic Clusters (pattern type: `pattern`)
- Groups of entities with dense interconnections
- Example: `quantum` + `arxiv` + `paper` + `loop quantum gravity` → "QHE/BHE research active"

## Implementation

### Script: `scripts/mulch-integration.cjs`

```javascript
// 1. Query graph for top entities (last 7 days)
const rising = graph.query(`
  SELECT name, entity_type, mention_count, last_seen
  FROM entities
  WHERE last_seen > datetime('now', '-7 days')
  ORDER BY mention_count DESC
  LIMIT 50
`);

// 2. Filter: mention_count > 5 AND novelty check
// 3. For each, check if already in .mulch/expertise/*.jsonl this week
// 4. If new, record: mulch record <domain> --type <type> ...
```

### Cron Configuration
- **Schedule**: `6 3 * * *` (3:06 AM IST, after existing mulch cron at 3:00 AM)
- **Target**: `isolated` agent session
- **Model**: `kimi/k2.7-code`
- **Timeout**: 300 seconds

## Deduplication Rules
1. **Entity-level**: Skip if entity name appears in any `.mulch/expertise/*.jsonl` file with `recorded_at` within 7 days
2. **Topic-level**: Skip if 3+ overlapping entities already recorded
3. **Error-level**: Skip if same error type recorded in last 3 days
