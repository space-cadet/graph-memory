## Goal

Target: <50ms for 95th percentile queries, with high-quality full-text results.

## Current Performance Baseline

| Query Type | Current Latency | Bottleneck |
|-----------|-----------------|------------|
| Exact match | ~1-5ms | SQLite index (good) |
| Fuzzy `LIKE %x%` | ~50-200ms | Table scan (bad) |
| Semantic (all embeddings) | ~100-500ms | JS cosine similarity |
| BFS traversal | ~10-50ms | Small graph size |

## Why Not Rust?

**Rejected**: The SQLite C API is already optimal for this workload. `better-sqlite3` is a C++ binding that calls SQLite directly — same performance as `rusqlite`. A Rust rewrite would take days and save milliseconds. The real wins are in SQLite features, not language.

## Optimization Plan

### 1. SQLite FTS5 (Expected: 10-100x speedup for text search)

```sql
-- Create virtual FTS5 table
CREATE VIRTUAL TABLE entities_fts USING fts5(
  name, 
  canonical_name, 
  description,
  content='entities',
  content_rowid='id'
);

-- Keep FTS index in sync via triggers
CREATE TRIGGER entities_fts_insert AFTER INSERT ON entities BEGIN
  INSERT INTO entities_fts(rowid, name, canonical_name, description)
  VALUES (new.id, new.name, new.canonical_name, new.description);
END;

-- Query: replaces LIKE %query%
SELECT * FROM entities_fts WHERE entities_fts MATCH 'quantum computing';
```

**Trade-off**: FTS5 adds ~20% to DB size, requires SQLite compiled with FTS5 (default in most builds).

### 2. In-Memory LRU Cache (Expected: sub-millisecond for hot queries)

```javascript
const cache = new Map(); // Simple LRU: max 20 entries
const CACHE_MAX = 20;

function getCached(key) {
  const entry = cache.get(key);
  if (entry && Date.now() - entry.ts < 60000) { // 60s TTL
    // Move to end (LRU)
    cache.delete(key);
    cache.set(key, entry);
    return entry.data;
  }
  return null;
}
```

**Cache keys**: `search:${query}:${type}:${limit}`, `stats`, `related:${entity}:${depth}`

### 3. WAL Mode (Already enabled? Check and verify)

```sql
PRAGMA journal_mode = WAL;
PRAGMA synchronous = NORMAL;
```

**Benefit**: Readers don't block writers. The queue worker can process sessions while queries run.

### 4. Query Optimization: LIMIT Early

Current `search-graph.cjs` fetches all fuzzy matches then slices. Better:
```sql
-- Add LIMIT to SQL, not JS
SELECT * FROM entities 
WHERE name LIKE ? 
ORDER BY mention_count DESC 
LIMIT ?;  -- Push limit to SQLite
```
