## Technical Details

### Native SQLite Fallback Chain
All scripts now try SQLite drivers in this order:
1. `better-sqlite3` (preferred, synchronous)
2. `node:sqlite` / `DatabaseSync` (Node 22+, synchronous, no npm dep)
3. `sqlite3` (async fallback)

This means the worker survives `node_modules` cleanup and restarts without manual intervention.

### Isolated MiniLM Runtime
`scripts/embeddings.cjs` resolves `@xenova/transformers` from:
1. `GRAPH_MEMORY_TRANSFORMERS_DIR` (env override)
2. `~/.cache/graph-memory-transformers` (default isolated dir)
3. `__dirname` (fallback to local node_modules)

This prevents version conflicts with the graph's other dependencies.

### BLOB Decoding Bug (Fixed)
**Problem:** `node:sqlite` returns BLOBs as `Uint8Array`, while `better-sqlite3` returns `Buffer`. Direct `new Float32Array(row.embedding)` treated each byte as a float, producing garbage vectors.

**Fix:** `blobToFloat32(blob)` in `query-bridge.cjs`:
- Handles `Float32Array` (pass-through)
- Handles `Array` (convert)
- Handles `ArrayBuffer.isView` (Uint8Array/Buffer → use `.buffer` with correct offset)
- Handles `ArrayBuffer` (direct)
- Throws on invalid length (must be divisible by 4)
